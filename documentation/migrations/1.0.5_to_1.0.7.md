# Migration Guide — 1.0.5 → 1.0.7

This guide covers the breaking changes introduced by the zen-mode performance
refactor and the scroll-strategy system (which replaces the standalone
typewriter scrolling). Every change is listed with a before/after example and
a migration step.

> [!NOTE]
> The jump skips 1.0.6: the `novident_editor_rich_text` package gets a
> version bump for the `resolveStyle` interface change (see
> [Span pipeline](#span-pipeline-resolvestyle)).

---

## Zen mode

### Dimming is applied through the span pipeline (no more decorator)

`ZenModeController.textSpanDecorator()` was removed. The color neutralization
now happens inside `ZenSpanPipeline`, which `attach()` registers on the
`EditorState` automatically. **Remove the `textSpanDecorator` parameter from
your `EditorStyle`.**

```dart
// Before
final zenController = ZenModeController();
zenController.attach(editorState: editorState);

NovidentEditor(
  editorState: editorState,
  editorStyle: EditorStyle.desktop(
    textSpanDecorator: zenController.textSpanDecorator(),
  ),
  blockWrapper: zenController.blockWrapper,
);

// After
final zenController = ZenModeController();
zenController.attach(editorState: editorState);

NovidentEditor(
  editorState: editorState,
  // no textSpanDecorator — the dimming goes through the span pipeline.
  blockWrapper: zenController.blockWrapper,
);
```

### `ZenModeBlockWrapper` replaced by `ZenModeBlock`

The old opacity-based wrapper (`AnimatedOpacity` + `saveLayer`) is gone. The
new `ZenModeBlock` provides the dimmed state via `ZenModeScope` and only
rebuilds when its own focus state flips (O(1)). You don't construct it
directly — `zenController.blockWrapper` returns it.

If you referenced `ZenModeBlockWrapper` directly, switch to `ZenModeBlock`
(only needed for custom wrappers):

```dart
// Before
ZenModeBlockWrapper(
  editorState: editorState,
  configuration: controller,
  node: node,
  child: child,
);

// After
ZenModeBlock(
  configuration: controller,
  focusedTopLevelRange: controller.focusedTopLevelRange,
  node: node,
  child: child,
);
```

### Scroll fields removed from `ZenModeConfiguration`

`centerFocusedBlock`, `centerAlignment`, `scrollDuration` and `scrollCurve`
were removed from `ZenModeConfiguration`. Typewriter scrolling is now a
standalone scroll strategy — pass a `TypewriterScrollStrategy` to
`NovidentEditor.scrollStrategies` (see [Scroll strategies](#scroll-strategies)).
The strategy centers **instantly** (no `scrollDuration`/`scrollCurve`).

```dart
// Before
const ZenModeConfiguration(
  centerFocusedBlock: true,
  centerAlignment: 0.5,
  scrollDuration: Duration(milliseconds: 300),
);

// After — typewriter scrolling is a standalone scroll strategy
NovidentEditor(
  editorState: editorState,
  scrollStrategies: const [TypewriterScrollStrategy(alignment: 0.5)],
);
```

## Scroll strategies

> **New in 1.0.7:** the editor now delegates scrolling to a list of
> `ScrollStrategy` policies, mirroring the `KeyboardStrategy` pattern. This is
> the way to customize scroll behavior (e.g. typewriter centering).

### `NovidentEditor.scrollStrategies` (new)

Pass a list of strategies; on each selection change the editor consults them
**in order** and the first one that returns `ScrollDecision.handled` wins. If
none handles it, the built-in edge-follow runs.

```dart
// Enable typewriter centering via a scroll strategy
NovidentEditor(
  editorState: editorState,
  editorScrollController: editorScrollController,
  scrollStrategies: const [TypewriterScrollStrategy(alignment: 0.45)],
);
```

An empty list (the default) keeps the built-in edge-follow:

```dart
NovidentEditor(
  editorState: editorState,
  scrollStrategies: const [], // default edge-follow
);
```

### The `ScrollStrategy` interface

```dart
enum ScrollDecision {
  ignored, // not mine — let the next strategy (or the default edge-follow) handle it
  handled, // I handled the scroll (or decided no scroll is needed) — stop dispatch
}

abstract class ScrollStrategy {
  const ScrollStrategy();
  ScrollDecision onSelectionChanged(ScrollStrategyContext ctx);
}

class DefaultScrollStrategy extends ScrollStrategy {
  const DefaultScrollStrategy();
}
```

`ScrollStrategyContext` carries everything a strategy needs: `editorState`,
`selection`, `reason`, `scrollService`, `editorScrollController`, the
already-measured `selectionRects`, and a per-editor `state` store for
strategies that need to remember something between events (strategies are
`const`, so any mutable state lives in `ctx.state`).

Extend `DefaultScrollStrategy` and return `ScrollDecision.ignored` for the
cases you don't own — the built-in edge-follow then runs as the fallback.

See **[Scroll Strategies](../scroll-strategies.md)** for the full
API and examples.

## Span pipeline (`resolveStyle`)

`NovidentTextSpanPipeline.resolveStyle` now accepts two **optional**
parameters: `node` and `context`. Existing calls keep compiling unchanged —
the parameters default to `null`. Custom pipelines that override
`resolveStyle` must update their signature:

```dart
// Before
@override
TextStyle resolveStyle(
  Attributes? attributes,
  TextStyle base,
  TextStyleConfiguration textStyleConfiguration,
) { ... }

// After
@override
TextStyle resolveStyle(
  Attributes? attributes,
  TextStyle base,
  TextStyleConfiguration textStyleConfiguration, {
  Node? node,
  BuildContext? context,
}) { ... }
```

> [!IMPORTANT]
> This is a breaking change to the `novident_editor_rich_text` package
> interface — bump its version and update the constraint in your
> `pubspec.yaml` (`novident_editor_rich_text: ^1.0.7`).

### Pipeline composition hook

`EditorState` exposes a generic hook for optional modes to compose over the
effective pipeline (spell check or default):

```dart
editorState.setSpanPipelineWrapper(
  (effective) => MyPipeline(effective),
);
editorState.clearSpanPipelineWrapper();
```

`ZenModeController.attach()`/`detach()` manage this automatically — you only
need the hook if you build your own pipeline-wrapping mode.

## Summary of removed symbols

| Removed | Replacement |
|---|---|
| `ZenModeController.textSpanDecorator()` | none — dimming via `ZenSpanPipeline` (auto-registered on `attach`) |
| `ZenModeBlockWrapper` | `ZenModeBlock` (returned by `zenController.blockWrapper`) |
| `ZenModeController.typewriter` | `TypewriterScrollStrategy` (via `NovidentEditor.scrollStrategies`) |
| `ZenModeController.shouldDisableNativeAutoScroll` | none — strategies replace the kill-switch |
| `ZenModeController.centerBlockAt` | none — move the caret to the block instead |
| `ZenModeConfiguration.centerFocusedBlock` | `TypewriterScrollStrategy` (always centers) |
| `ZenModeConfiguration.centerAlignment` | `TypewriterScrollStrategy.alignment` |
| `ZenModeConfiguration.scrollDuration` | none — the strategy centers instantly |
| `ZenModeConfiguration.scrollCurve` | none — the strategy centers instantly |
| `TypewriterScrollController` | `TypewriterScrollStrategy` (via `NovidentEditor.scrollStrategies`) |
| `TypewriterScrollConfig` | `TypewriterScrollStrategy` |
| `EditorState.typewriter` | `TypewriterScrollStrategy` (via `NovidentEditor.scrollStrategies`) |
